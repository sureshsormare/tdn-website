The mechanism

One lens is one decision view over the same resolved data.

A lens does not own its data. Every source is resolved to one canonical molecule key first, then each lens reads that resolved layer and arranges it around one question. Change the question, change the lens; the numbers underneath do not move.

  • One key per molecule. Spending, prescribers, approvals, patents, plants, plans and shipments all land on the same key before anything is counted.
  • Source and vintage on every figure. Each number on screen says which register it came from and which year or release it reflects.
  • Max, not sum, across overlapping registers. Where two registers describe the same prescriptions, the platform takes the larger, never the total. That is what stops double counting.
  • Read-only. Nothing writes back. The lenses, the Atlas and Ask are views, not editors.

How it fits together

Sources in, one spine, nine lenses out.

Registers arrive on different grains: a claim, an approval, a plant, a plan, a shipment. Each is resolved to the molecule key, overlaps are taken at their maximum, a vintage is stamped, and only then does a lens read it.

Ask · NLQ

Ask anything, get a verified number.

The Ask console sits on the same spine as the lenses. Type a question in plain English. The service finds the right tables, writes and checks the SQL, runs it read-only and verifies every headline number against the rows before it answers.

  • Same data as the lenses. An Ask answer and a lens figure agree because they read the same resolved layer.
  • Source shown. Each answer names the register and vintage it came from.
  • Asks back when it must. If the question cannot be answered as put, it offers a clarification instead of a wrong number.
